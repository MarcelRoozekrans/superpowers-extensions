# Anti-Slop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a 14th plugin, `anti-slop`, whose skill silently rewrites AI prose tics out of any text Claude is about to publish, in English and Dutch.

**Architecture:** A markdown skill (`SKILL.md`) that routes to one of two pattern catalogues by language. A small Node script parses the catalogues' vocabulary `Match` regexes and greps text for them. The tests and the GREEN pressure check use it, and the skill can run it on long files. The plugin is registered in the nine registries that `check:registries` enforces, plus the README.

**Tech Stack:** Markdown skills, Node ≥ 20 ESM (`node:test`), markdownlint-cli2, existing `scripts/check-*.mjs` guards.

**Spec:** `docs/superpowers/specs/2026-10-30-anti-slop-design.md`

## Global Constraints

- Prose only: no code-slop patterns.
- The skill fires on publishable text (commit message, PR title/body, issue, issue/PR/review comment, README, docs, spec/design doc, CHANGELOG prose, release notes) and on demand ("de-slop this", "anti-slop this file"). No hook.
- On a hit: rewrite silently and add no report. On-demand file runs edit in place and leave a diff.
- Rewrites keep every fact, number, path, code span, URL, template heading and conventional-commit header. No nested parentheses in commit bodies (release-please).
- Languages: English and Dutch, one catalogue each. A mixed draft uses the dominant language. Text the user dictated verbatim is published as written.
- Every catalogue entry has five fields: pattern name, the tell, bad example, plain rewrite, why it reads as machine-written. Four families: Vocabulary, Structure, Tone, Substance.
- `SKILL.md` and the catalogues pass their own check, with **Bad:** lines exempt.
- Commit scope `anti-slop` (Task 4 adds it to commitlint's scope-enum). No Claude signatures or session links in commits or PRs.

## Review Focus

- **A rewrite drops a fact.** A PR body that lists three changed files and an issue number has to keep all of them after the rewrite. Owned by Task 5's fact-retention check.
- **A conventional-commit header gets "improved".** `fix(x): …` must keep its type, scope and colon. Owned by Task 5 (commit brief).
- **A regex matches inside a word.** "robustness" in a quoted error message, or "leverage" inside a code span, must not count as a hit. Owned by Task 1 (word boundaries + code-span stripping tests).
- **Dutch text scanned with the English catalogue.** Owned by Task 1 (scanner takes an explicit catalogue path) and Task 4 (language routing in SKILL.md).
- **The skill fires on a plain chat question.** Owned by Task 5's trigger check.

### Task 1: Vocabulary scanner

**Files:**

- Create: `plugins/anti-slop/skills/anti-slop/scripts/scan.mjs`
- Create: `plugins/anti-slop/skills/anti-slop/scripts/scan.test.mjs`
- Create: `plugins/anti-slop/skills/anti-slop/scripts/fixtures/catalogue.md`

**Interfaces:**

- Produces:
  - `parseCatalogue(markdown: string) => Array<{ name: string, regex: RegExp }>`. It collects every line of the form ``**Match:** `<regex>` `` and uses the nearest preceding level-2 or level-3 heading as `name`. Regexes are compiled with flags `giu`.
  - `scanText(text: string, patterns) => Array<{ name: string, match: string, line: number }>`. Before matching it strips fenced code blocks, inline code spans, and lines starting with `**Bad:**` or `**Match:**`. Stripped lines become empty lines so line numbers stay accurate.
  - CLI: `node scan.mjs <catalogue.md> <file...>` prints `file:line  name  "match"` per hit and exits 1 on any hit, 0 when clean.
- Catalogue format contract (Tasks 2–3 must follow it): one entry per `### <pattern name>` heading. Vocabulary entries carry one or more `**Match:**` lines, and the regexes include their own `\b` boundaries.

- [ ] **Step 1: Write the fixture and failing tests** in `scan.test.mjs`. The fixture has two entries: `### Delve` with ``**Match:** `\bdelv(e|es|ing)\b` `` and a `**Bad:** We delve into it.` line, and `### Worth noting` with ``**Match:** `\bit(?:'|’)s worth noting\b` ``. Tests:
  - `parseCatalogue` returns 2 patterns named `Delve` and `Worth noting`.
  - `scanText("Let's delve in.\nFine.", p)` gives one hit `{ name: 'Delve', match: 'delve', line: 1 }`.
  - `scanText("Delving deeper", p)` gives one hit (case-insensitive).
  - `scanText("the delver", p)` gives zero hits (word boundary).
  - `` scanText("run `delve` now", p) `` gives zero hits (inline code).
  - A fenced block containing "delve" gives zero hits, and a hit after the fence reports its true line number.
  - `scanText("**Bad:** we delve", p)` gives zero hits.
  - `scanText("It’s worth noting that", p)` gives one hit (curly apostrophe).
  - CLI on a clean temp file exits 0; on a dirty file it exits 1 and stdout contains `Delve`.
- [ ] **Step 2: Run** `node --test plugins/anti-slop/skills/anti-slop/scripts/scan.test.mjs`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement** `scan.mjs` to the interfaces above (ESM, no dependencies; the CLI runs only when `import.meta.url` is the entry point).
- [ ] **Step 4: Run** `npm test`. Expected: all suites pass, including the new one.
- [ ] **Step 5: Commit** `feat(anti-slop): add vocabulary scanner for pattern catalogues`. Commitlint's scope-enum lacks `anti-slop` until Task 4, so run `npx commitlint --from origin/master` only after Task 4.
