# Wizard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a 16th plugin, `wizard`, ported from Matt Pocock's MIT skill. Claude scopes a manual procedure and writes a bash wizard from a vendored template, and a check script verifies the result.

**Architecture:** `template.sh` is upstream's template plus one shellcheck fix, pinned by SHA-256 in `NOTICE.md`. `scripts/check.mjs` runs static checks on a generated wizard: syntax, shellcheck on the stages section, library unchanged, stage count, example removed, secret names against the workflows, and the executable bit. `SKILL.md` adapts upstream's four steps, asks the user through AskUserQuestion, and runs published text through anti-slop.

**Tech Stack:** Bash, Node ≥ 20 ESM (`node:test`), shellcheck (optional locally, preinstalled on GitHub Ubuntu runners), Markdown skills, markdownlint-cli2, `scripts/check-*.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-31-wizard-design.md`

## Global Constraints

- Plugin name and commit scope: `wizard`. Task 3 adds the scope to commitlint; until then, commit tasks 1–2 under scope `wizard` anyway (the commitlint job runs on the PR, after Task 3).
- Commits: no Claude signatures, no session links, no nested parentheses in bodies. Commit messages, PR text, README and SKILL.md prose go through `anti-slop`.
- Upstream: `mattpocock/skills`, path `skills/engineering/wizard/`, commit `a496f5513d4a4cf889bc48e189e579f4b0bdf6aa`. Upstream `template.sh` SHA-256: `6566f147299bc6f1d941e64591ed04385416d543e11f96f564c7228f5018d0ed`.
- The only change from upstream: `template.sh` line 114, `$e[Enter keeps current]` becomes `${e}[Enter keeps current]`.
- The library is every line above the line starting `# STAGES:`. The stages section is that line and everything after it.
- Upstream copy for reference: `git clone --depth 1 https://github.com/mattpocock/skills.git` into the scratchpad.

## Review Focus

- **A `.env` value holding a single quote or `$`.** `write_env` must store it so `_existing` reads back the same value on re-run. Owned by Task 1, runtime test with value `it's $HOME`.
- **A wizard whose workflow reads secrets via `${{ secrets.NAME }}` with spaces, or in a `.yaml` file.** Both must be found. Owned by Task 2.
- **A `stage` call in a comment or an indented `stage` inside an `if`.** The comment must not count; the indented call must. Owned by Task 2.
- **A shellcheck finding in the library of a hand-edited wizard.** It must be reported by the library check, not lost because shellcheck is scoped to stages. Owned by Task 2 (edited-library fixture fails on `library`).
- **No `.github/workflows` in the repo.** The secret-name check must `skip`, not fail or crash. Owned by Task 2.

### Task 2: check.mjs

**Files:**

- Create: `plugins/wizard/skills/wizard/scripts/check.mjs`
- Create: `plugins/wizard/skills/wizard/scripts/check.test.mjs`
- Create: `plugins/wizard/skills/wizard/scripts/fixtures/repo/.github/workflows/ci.yml` (reads `secrets.SECRET_KEY` and `secrets.GITHUB_TOKEN`)
- Create: `plugins/wizard/skills/wizard/scripts/fixtures/repo/.github/workflows/deploy.yaml` (reads `${{ secrets.DEPLOY_TOKEN }}` with spaces)

**Interfaces:**

- Consumes: `template.sh`, `fixtures/runtime-wizard.sh` (Task 1).
- Produces: `export function checkWizard(wizardPath: string, { repo?: string, templatePath?: string } = {}) => { ok: boolean, results: Array<{ check: string, status: 'ok'|'fail'|'skip'|'warn', detail: string }> }`. `templatePath` defaults to `../template.sh` relative to `check.mjs`. Check names are exactly `syntax`, `shellcheck`, `library`, `stages`, `example`, `secrets`, `executable`. `secrets` may add a second `warn` result.
- Produces CLI: `node check.mjs <wizard.sh> [--repo <dir>]`. It prints one line per result as `<status padded to 4> <check>: <detail>`, exits 1 when `ok` is false, and exits 2 on bad usage. `repo` defaults to the current directory.

Rules (from the spec):

- `stages` counts lines matching `/^\s*stage\s+["']/` between `run_wizard() {` and `run_wizard "$@"`, and compares the count with `TOTAL_STAGES=<n>` in the same region.
- `example` fails when the file contains `Example stage: replace with your real steps`.
- `secrets` collects `set_secret NAME` names, then reads `/secrets\.([A-Za-z_][A-Za-z0-9_]*)/g` from every `.yml` and `.yaml` file under `<repo>/.github/workflows`.
  - It fails listing each wizard name the workflows don't read.
  - It warns listing each workflow name except `GITHUB_TOKEN` that the wizard doesn't set.
  - It skips when the directory is missing.
- `shellcheck` runs `shellcheck -f json` on the whole file and fails only on findings whose `line` falls in the stages section.

- [ ] **Step 1: Write the failing tests.** Build each bad wizard in a temp dir from `runtime-wizard.sh` with one string edit, `chmod 755`, so no library copy is stored twice:
  - `good wizard passes`: `runtime-wizard.sh` with `repo` = `fixtures/repo`. `ok` is true. `secrets` is ok, and a `warn` names `DEPLOY_TOKEN` but not `GITHUB_TOKEN`.
  - `stage count mismatch fails`: `TOTAL_STAGES=1` → `TOTAL_STAGES=2`. `stages` is `fail` with `TOTAL_STAGES=2 but 1 stage call`.
  - `commented and indented stage calls`: before `finish`, insert the lines `# stage "x"`, `if true; then`, `stage "Two"` indented by two spaces, and `fi`, and set `TOTAL_STAGES=2`. `stages` is `ok`.
  - `edited library fails`: replace `printf '\n'; warn "still to do by hand:"` with `echo todo`. `library` is `fail`.
  - `leftover example fails`: append the comment `# ── Example stage: replace with your real steps` in the stages section. `example` is `fail`.
  - `unknown secret fails`: `set_secret SECRET_KEY` → `set_secret STRIPE_KEY`. `secrets` is `fail` and names `STRIPE_KEY`.
  - `no workflows skips`: `repo` is an empty temp dir. `secrets` is `skip`.
  - `syntax error fails`: append `if then`. `syntax` is `fail`.
  - `not executable fails`: `chmod 644`. `executable` is `fail`.
  - `CLI exit codes`: good → 0; leftover example → 1; no arguments → 2.
- [ ] **Step 2: Run** `node --test plugins/wizard/skills/wizard/scripts/check.test.mjs`. Expected: FAIL, because `check.mjs` is missing.
- [ ] **Step 3: Implement** `checkWizard` and the CLI in `check.mjs`. Use `spawnSync('bash', ['-n', path])`. For shellcheck, skip when `spawnSync('shellcheck', ['--version'])` reports `ENOENT`.
- [ ] **Step 4: Run** the tests. Expected: all pass. Also run `node check.mjs fixtures/runtime-wizard.sh --repo fixtures/repo` by hand, with shellcheck on `PATH`. Expected: exit 0 and a `shellcheck` ok line.
- [ ] **Step 5: Commit** `feat(wizard): add a check script for generated wizards`.
