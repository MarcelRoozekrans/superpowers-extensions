# Retro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a 16th plugin, `retro`, whose skill reads a session transcript, finds setup improvements, ranks them, and drives each to fixed, filed or dropped.

**Architecture:** A markdown skill (`SKILL.md` plus two references) and one Node script, `scripts/digest.mjs`, that streams a Claude Code JSONL transcript into a compact digest. One Sonnet subagent turns digest plus transcript into findings; the main agent runs the per-finding decision loop.

**Tech Stack:** Markdown, Node 26 builtins only (`node:fs`, `node:readline`, `node:test`).

**Spec:** `docs/superpowers/specs/2026-10-31-retro-design.md`

## Global Constraints

- Node builtins only; no new dependencies.
- `npm run lint:md`, `npm test`, `npm run check:registries`, `npm run check:conventions`, `npm run check:upstream` all pass at the end.
- Questions to the user go through AskUserQuestion with one option marked "(Recommended)".
- Never print a whole transcript record; any digest field taken from transcript text is truncated (inputs 120 chars, first prompt 200 chars).
- A missing field is reported as `unknown`, never `0`.
- Credit: "Adapted from Matt Pocock's skills (MIT)"; upstream commit `a496f55`; copyright line `Copyright (c) 2026 Matt Pocock`.
- No nested parentheses in commit bodies (release-please).
- Spec deviation: the licence goes in `NOTICE.md`, matching `compress-memory`, instead of `LICENSE-mattpocock-skills`. Task 2 updates the spec line.

## Review Focus

1. A transcript line over 100,000 characters (embedded image, huge tool result): its size is counted, its text never appears in the output.
2. A malformed JSON line or a truncated last line (session still running): counted under `malformed`, digest continues.
3. A `tool_use` with no matching `tool_result` (interrupted turn): listed as `unanswered`, not as a failure, no crash.
4. `tool_result.content` as an array of blocks (text, image, tool_reference) rather than a string: size is the sum of text lengths plus base64 data lengths.
5. A transcript with no `cost-state` and no `usage`: cost and tokens print `unknown`.

**Files:**

- Create: `plugins/retro/skills/retro/scripts/digest.mjs`

- Create: `plugins/retro/skills/retro/scripts/fixtures/subagents/agent-a1.jsonl` (synthetic, ~5 lines)

**Interfaces:**

- Produces:
  - `createDigester(opts?: { top?: number, longLine?: number }) -> { add(line: string, lineNo: number): void, result(): Digest }` (defaults `top: 10`, `longLine: 100000`)
  - `digestFile(path: string, opts?) -> Promise<Digest>` (readline stream over `createDigester`)
  - `formatDigest(d: Digest, label?: string) -> string` (markdown text)
  - CLI: `node digest.mjs <transcript.jsonl> [--subagents] [--json] [--top N]`. `--subagents` also digests every `*.jsonl` in `<dirname>/<basename-without-.jsonl>/subagents/`, each under its own heading. Exit 2 with a usage line when the path is missing or unreadable.
  - `Digest` fields: `session {id, firstPrompt, start, end, models[], turns, tokens: {input, output, cacheRead, cacheCreate} | 'unknown', costUSD | 'unknown'}`, `biggest[] {lineNo, tool, input, size}`, `repeatedReads[] {path, count, lines[]}`, `repeatedCommands[] {command, count, lines[]}`, `failures[] {lineNo, tool, input, retriedAt: number | null}`, `searchChurn[] {startLine, searches, thenRead}`, `subagents[] {lineNo, description, model | 'unset', resultSize}`, `unanswered[] {lineNo, tool}`, `longLines[] {lineNo, length}`, `malformed: number`, `unknownTypes: {[type]: count}`.

Record facts, observed in real transcripts:

- `assistant`: `message.model`, `message.usage` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`), `message.content[]` items with `type: "tool_use"`, `id`, `name`, `input`.
- `user`: `message.content` is a string (human prompt) or an array; array items with `type: "tool_result"`, `tool_use_id`, `content` (string or block array), optional `is_error: true`. A human prompt is a `user` record whose content is a string or has a `text` block and no `tool_result`, and whose `isMeta` is not true.
- `cost-state`: `totalCostUSD`.
- Known types to ignore silently: `attachment`, `queue-operation`, `last-prompt`, `atis-latch`, `system`, `summary`. Anything else goes in `unknownTypes`.
- Input summary per tool: Bash → `input.command`; Read/Edit/Write → `input.file_path`; Grep/Glob → `input.pattern`; Agent/Task → `input.description`; other → first string value. Truncate to 120.
- Retry: a failure is `retriedAt` the line of the next `tool_use` of the same tool within the next 5 tool calls whose input summary shares its first 40 characters; otherwise `null`.
- Search churn: a run of ≥3 consecutive Grep/Glob calls (Bash `find`/`grep`/`rg` count too) ending in a Read; report runs only.
- Repeated: Read of the same `file_path` ≥2 times; Bash of the identical command ≥2 times.
