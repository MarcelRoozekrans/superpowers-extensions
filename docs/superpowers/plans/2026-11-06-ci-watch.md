# ci-watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `ci-watch` plugin that lets CI results drive the work (wait, fix red CI, merge when green, follow the release), wired into `unattended`, `project-orchestration` and `pre-push-review`.

**Architecture:** One skill (`ci-watch`) with Wait, Merge and Release stages, and one `PostToolUse` hook that tells the agent to start Wait when a PR gets opened. The hook's logic lives in pure, tested functions in `ci-watch.mjs`; the hook script is a thin fail-open wrapper, as in `unattended` and `context-budget`.

**Tech Stack:** Markdown skills, Node `.mjs` hooks using built-ins only, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-06-ci-watch-design.md`

## Global Constraints

- Hooks never fail a turn: any error ends in `process.exit(0)` with no output.
- Node built-ins only; no new dependencies.
- Hook scripts live under `plugins/ci-watch/skills/ci-watch/scripts/` and are referenced from `plugins/ci-watch/hooks/hooks.json` through `${CLAUDE_PLUGIN_ROOT}`.
- No literal `git commit -m` or `git tag -a` in any SKILL.md (enforced by `npm run check:conventions`). Commits are described as "commit following the repo's commit rules".
- Commit scopes must be in `commitlint.config.js` scope-enum; this plan adds `ci-watch`. Use `ci-watch`, `unattended`, `project-orchestration`, `pre-push-review` or `readme`.
- No `Co-Authored-By: Claude` trailer, no `claude.ai/code/session_` link and no nested parenthesis in any commit message.
- `--admin` only to pass the review rule, after every required check passed on an up-to-date head with no conflicts. Never `--auto`, never another bypass.
- Release PRs (head branch starting `release-please--`, or opened by the repo's `Released by` tool) are never merged by the skill.
- Default CI wait limit: 60 minutes. Red-CI fix rounds: 3.
- Credit Devleaps/tempa-config-template (MIT) for the merge flow.

## Review Focus

- A `gh pr create` that failed prints no PR URL: the hook stays silent.
- Malformed or empty hook stdin: exit 0, no output.
- Parentheses inside a fenced code block, and unbalanced ones such as `:)`, are left untouched by `sanitizeBody`.
- An MCP `create_pull_request` response whose JSON also holds non-PR GitHub URLs (repo, user): only the `/pull/<n>` URL is taken.
- `SUPERPOWERS_UNATTENDED=1`: the hook stays silent even on a real PR creation.

## Checks

- build: `npm run lint:md && npm run check:registries && npm run check:conventions`
- tests: `npm test`

### Task 1: Hook logic and the PR-opened hook

**Files:**

- Create: `plugins/ci-watch/skills/ci-watch/scripts/ci-watch.mjs`

- Test: `plugins/ci-watch/skills/ci-watch/scripts/ci-watch.test.mjs`

**Interfaces:**

- Produces, from `ci-watch.mjs`:
  - `isPrCreate(toolName: string, toolInput: object) -> boolean`: true for `Bash` whose `toolInput.command` matches `/\bgh\s+pr\s+create\b/`, and for any tool name ending in `create_pull_request`.
  - `findPrUrl(toolResponse: unknown) -> string | null`: first match of `/https:\/\/github\.com\/[\w.-]+\/[\w.-]+\/pull\/\d+/` in `JSON.stringify(toolResponse)` (a plain string is searched as is).
  - `prOpenedContext(env: object, payload: {tool_name, tool_input, tool_response}) -> string | null`: `null` when `env.SUPERPOWERS_UNATTENDED === '1'`, when not a PR creation, or when no URL; otherwise exactly ``PR <url> was opened. Invoke `ci-watch` and run its Wait stage for this PR.``
  - `sanitizeBody(text: string) -> string`: used by the Merge stage (Task 2).

- [ ] **Step 1: Write the failing tests** in `ci-watch.test.mjs`, in the style of `plugins/unattended/skills/unattended/scripts/unattended.test.mjs` (`node:test`, `assert/strict`, `spawnSync` for the hook script):
  - `isPrCreate`: `('Bash', {command: 'gh pr create --fill'})` true; `('Bash', {command: 'gh pr view 3'})` false; `('mcp__plugin_github_github__create_pull_request', {})` true; `('Read', {})` false.
  - `findPrUrl`: `{stdout: 'https://github.com/o/r/pull/12\n'}` → `'https://github.com/o/r/pull/12'`; an MCP-shaped `{content: [{type: 'text', text: '{"url":"https://github.com/o/r/pull/7","user":{"html_url":"https://github.com/u"}}'}]}` → the `/pull/7` URL; `{stdout: '', stderr: 'GraphQL: ...'}` → `null`.
  - `prOpenedContext`: real creation → the exact message above; same payload with `{SUPERPOWERS_UNATTENDED: '1'}` → `null`; failed creation (no URL) → `null`.
  - `sanitizeBody`:
    - drops a line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (case-insensitive on the key), keeps `Co-Authored-By: Jane <j@example.com>`;
    - drops every line containing `claude.ai/code/session_`;
    - `'[Singleton(As = typeof(IDetector), AllowMultiple = true)]'` → `'[Singleton(As = typeof[IDetector], AllowMultiple = true)]'`;
    - `'a (b (c (d)))'` → `'a (b [c [d]])'`;
    - `'smile :)'` and `'open ( only'` unchanged;
    - lines inside a ```` ``` ```` fence unchanged, nested parens included;
    - trailing blank lines left by removals are trimmed; text with nothing to change comes back identical.
  - Hook script via `spawnSync('node', [prOpenedPath], {input})`: a PR-creation payload prints JSON whose `hookSpecificOutput.hookEventName` is `'PostToolUse'` and `additionalContext` is the message; `input: 'not json'` and `input: ''` exit 0 with empty stdout; with `SUPERPOWERS_UNATTENDED=1` in env, empty stdout.

- [ ] **Step 2: Run to verify they fail**

Run: `node --test plugins/ci-watch/skills/ci-watch/scripts/ci-watch.test.mjs`
Expected: FAIL, module `./ci-watch.mjs` not found.

- [ ] **Step 3: Implement `ci-watch.mjs`** with the four exports above. `sanitizeBody` walks line by line, toggling a fence flag on lines starting with ```` ``` ````; outside fences it scans characters with a stack: a `(` at depth ≥ 1 becomes `[` and pushes `]`, a `(` at depth 0 pushes `)`, a `)` pops and emits the popped closer. When a line ends with the stack non-empty or a `)` arrives on an empty stack, the line is returned unchanged.

- [ ] **Step 4: Implement `pr-opened.mjs`**: read stdin, parse, call `prOpenedContext(process.env, payload)`, and when non-null write `{hookSpecificOutput: {hookEventName: 'PostToolUse', additionalContext}}`. - [ ] **Step 5: Write `hooks.json`**: one `PostToolUse` entry, matcher `Bash|mcp__.*__create_pull_request`, command `node "${CLAUDE_PLUGIN_ROOT}/skills/ci-watch/scripts/pr-opened.mjs"`, timeout 5.

- [ ] **Step 6: Run tests to verify they pass**

Run: `node --test plugins/ci-watch/skills/ci-watch/scripts/ci-watch.test.mjs`
Expected: PASS, all tests.
